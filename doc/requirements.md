# 玄智（XUANZHI）机器人模拟器 - 需求文档 v2

## 一、项目背景

### 1.1 目标平台
- **主控器**: IE1 竞技机器人主控器
- **编程环境**: 玄智 XUANZHI 图形化编程（基于 Google Blockly）
- **文件格式**: `.XUANZHI` / `.xuanzhi` (XML)

### 1.2 核心目标
开发模拟器，解析 `.XUANZHI` 文件，在电脑上仿真执行，无需烧录到硬件即可调试。

## 二、硬件配置（已确认）

| 组件 | 配置 | 说明 |
|------|------|------|
| 主控 | IE1 | 竞技机器人主控器 |
| 电机 | 4个 (编号1-4) | 实际使用2号和3号做差速驱动 |
| 遥控通道 | 至少4个 (1,2,6,7) | 用于读取遥控器输入值 |

### 2.1 电机配置推测
```
  [1] [2]    ← 左侧电机组
     ║
  [机器人]   ← 车体
     ║
  [3] [4]    ← 右侧电机组
```
- **直行**: 电机2=正速, 电机3=负速 (如 60/-58)
- **左转**: 电机2=正速, 电机3=0 (如 70/0)
- **右转**: 电机2=0, 电机3=负速 (如 0/-35)
- **后退**: 电机2=负速, 电机3=正速 (如 -60/58)
- **停止**: 所有电机 = 0

## 四、模拟程度对比（回答用户问题）

### 4.1 纯逻辑仿真 vs 2D动画

| 特性 | 纯逻辑仿真 | 2D动画模拟 |
|------|-----------|-----------|
| **显示方式** | 控制台文本/日志 | Canvas画布 + 图形 |
| **开发难度** | ⭐ 低 (1-2天) | ⭐⭐⭐ 中 (3-5天) |
| **调试体验** | 看日志推断行为 | 直观看到运动轨迹 |
| **典型输出** | `[0.5s] M2=60 M3=-58 (直行)` | 🤖→→→ (小车图标移动) |
| **适用场景** | 快速验证逻辑正确性 | 演示、教学、完整调试 |

### 4.2 各级别效果示意

## 五、技术选型建议

### 5.1 方案对比

| 方案 | 优势 | 劣势 | 适用场景 |
|------|------|------|----------|
| **Python + Tkinter/PyGame** | 快速开发, 生态丰富 | 需要Python环境 | 原型开发 ⭐推荐 |
| **Web JS (HTML/CSS/JS)** | 无需安装, 跨平台 | 无文件系统访问权限 | 在线版 |
| **Electron** | Web技术+桌面能力 | 打包体积大(~150MB) | 正式发布版 |
| **C++/Qt** | 性能最好 | 开发周期长 | 工业级应用 |

### 5.2 推荐: Python 方案
```python
# 技术栈
- 语言: Python 3.x
- GUI: Pygame (2D渲染) 或 Tkinter (自带)
- XML解析: xml.etree.ElementTree (标准库)
- 包管理: pip / requirements.txt
```

**理由**:
1. Python 处理 XML 非常方便（标准库 `xml.etree`）
2. Pygame 提供良好的 2D 渲染能力
3. 开发效率高，适合快速迭代
4. 您可以轻松阅读和修改代码

### 10.5 CAD 模型实测尺寸（2026-08-01）

从官方提供的模型文件解析得到（单位 mm，CAD 默认 mm）：

| 文件 | 状态 | 内容 |
|------|------|------|
| `小台风2-机身.stl` | ✅ 已下载解析 (904KB, 18520 面) | 机身网格包围盒 |
| `小台风2-模型总装.stp` | ❌ 404 下载失败（服务器限制/路径问题） | 未能取到含轮子的总装 |

**机身 STL 包围盒（已解析）**：

| 轴 | 范围 | 跨度 | 推断含义 |
|----|------|------|---------|
| X | 93.0 ~ 163.0 | **70.0** | 机身左–右宽度（轮子安装侧） |
| Y | 79.7 ~ 176.3 | **96.6** | 机身前–后长度 |
| Z | 0.0 ~ 27.5 | **27.5** | 机身高度（扁平机型） |

**据此更新的物理标定**（`robot_state.py`）：
- 轮子直径 `WHEEL_DIAMETER_MM = 44`（**官方案例课程 PDF 明确："小台风采用 44mm 直径的海绵轮"**；此前 45 为用户口述，已修正）
- 轮距 `WHEELBASE_MM = 75`（= 机身宽 70 + 轮子外伸估算；STP 未取到故为推断值，课程 PDF 未给精确轴距）
- `PX_PER_MM = 0.6` → 轮距对应屏幕 45px
- 反算 `K_OMEGA = K_V / L_pixel = 1.2 / 45 ≈ 0.0267`
- 验证：左转(70/0) ≈ -27°，右转(0/-35) ≈ +15°，整周期净左转 ≈ -46°

### 10.6 安装包固件实证（2026-08-01，来自 `XUANZHI Programmer` 安装目录）

用户提供安装后的程序（`C:\Program Files\xz\XUANZHI Programmer\resources`）与安装包
（`D:\文档\xuanzhi_programmer_setup_1.0.12.exe`）。从中提取到**固件源码编译产物**，可反推出
电机/通道的权威行为（`.c` 源码被厂商加密为哈希串，但 `.lst` 汇编列表未加密，可还原逻辑）：

**A. 积木 → 固件调用映射**（`static/generator/robot.js`，未加密）
- `robot_motor` → `xChannal_Motor_nSpeed_Run(MOTOR_MENU, NUM)`
- `robot_steering_engine` → `xChannal_SteeringEngine_RunTo_nAngle(STEERING_ENGINE_MENU, STEERING_NUM)`
- 速度取值范围在生成器里被 `alert('可选范围在-100~100之间')` 约束 → **确认 ±100**。

**B. 电机通道实现**（`M40D_CRSF/build/Controllable_object.lst` 反汇编还原）
```c
void xChannal_Motor_nSpeed_Run(uint8_t ch, int nSpeed){
    if(ch>4) ch=4; if(ch<1) ch=1;          // 通道限幅 1~4
    if(nSpeed>100) nSpeed=100; if(nSpeed<-100) nSpeed=-100;
    int pwm = 1500 + nSpeed * 5;           // 单位 us，标准 RC 电调/PWM 信号
    if(ch==1) Motion_Motor1(pwm);          // → TIM 比较寄存器，独立 PWM 通道
    if(ch==2) Motion_Motor2(pwm);
    if(ch==3) Motion_Motor3(pwm);
    if(ch==4) Motion_Motor4(pwm);
}
```
- **M1~M4 是 4 个独立的电机通道**（各接一个电调），不是左右差速两轮绑定。
- `pwm = 1500 + nSpeed*5`：nSpeed=0 → 1500μs（中位/停），±100 → 1000/2000μs（全反转/全正转）。
  → **模拟器把 speed 当无量纲输入、用 K_V/K_OMEGA 做视觉缩放是合理的**（真实硬件输出的是 PWM）。
- `Motion_Motor1~4`（`Motor.lst`）各自把 pwm 写入不同 TIM 比较寄存器，四者对称、无折损补偿。

**C. 关键结论（回答 Q1/Q2/Q4/Q5）**
| 问题 | 结论 | 证据 |
|------|------|------|
| Q1 电机编号 | M1~M4 四个独立通道；`test.XUANZHI` 只用 **M2(左)、M3(右)** 做移动 | B 节 + 程序只出现 M2/M3 |
| Q2 舵机/武器 | 舵机是**独立 API**（角度舵机），不占用电机通道 M1/M4 | `robot_steering_engine` 反汇编 |
| Q4 取值范围 | 全通道/速度统一 **-100~100** | robot.js 生成器 alert |
| Q5 正负方向 | 正负由"编程值→PWM"直接映射，极性由硬件接线决定；`right=-M3` 是模拟器为统一前进方向的约定 | B 节 pwm 公式 |
| Q7 标定系数 | `K_V/K_OMEGA` 确认仅为视觉缩放，非官方物理值 | B 节（真实硬件输出 PWM） |

**D. 对模拟器的修正**
- 停止机制：`.XUANZHI` 里"结束"是用户加在 `M1=0` 块上的 `<comment>` 标签，**非独立积木**
  （`static/msg/messages.js` 仅有 `CONTROL_STOP='stop'`，无"结束"）。解析器已补 `comment` 字段捕获并跳出 `forever`。
- 物理模型：`robot_state.py` 的 `left=motors[2]`、`right=-motors[3]` 与程序行为一致，方向正确。

### 10.7 官方案例课程 PDF 实证（2026-08-02）

资料来源：
- 在线教程：`https://wiki.xmindtech.com/zh/IE1软件教程-XUANZHIProgrammer`（仅软件操作说明，**无底层物理/通道参数**）
- 本地课程 PDF：`小台风2-案例课程.pdf`（含安装说明、程序解析、操作映射，**关键参数在此**）

**A. 遥控通道映射（R2 遥控器，默认模式）** —— 回答 Q3
| 通道 | 物理摇杆 | 含义 |
|------|---------|------|
| CH1 | 左摇杆 ↑↓ | 前进 / 后退 |
| CH2 | 右摇杆 ←→ | 左转 / 右转 |
| CH3 | 右摇杆 ↑↓ | 备用 |
| CH4 | 左摇杆 ←→ | 备用 |
| CH5~CH8 | 4 个肩键 | 自定义 |

> 课程强调：因小台风为双轮驱动，示例程序只用了 CH1/CH2（即左右轮）。这与 `test.XUANZHI` 只用 M2/M3 一致。

**B. 官方双轮驱动示例程序（4 接口公式）**
```
M1、M2 = CH1 - CH2
M3、M4 = (CH1 + CH2) * -1
```
- M1/M2 与 M3/M4 程序相反（轴对称安装的必然结果）。
- 验证（`CH1=50, CH2=0`）：M1/M2=50，M3/M4=-50 → 机器人以 50 前进。
  → **这正是 `right = -motors[3]` 的物理依据**：M3/M4 侧电机"负值为前进"。

**C. 电机轴对称安装（核心方向约定）** —— 坐实 Q5/Q8
> "为使两个电机的出轴都向外连接轮毂，两电机需按轴对称方向安装。因此当两电机的输入数值相同而
> 方向相反时，机器人能够前进。"
- `test.XUANZHI` 直行段 `M2=+60, M3=-58` 正是此约定（异号→前进），与模拟器 `left=motors[2]`/`right=-motors[3]` 完全吻合。
- 左转段 `M2=70, M3=0`：仅左轮前进 → 绕右轮左转；右转段 `M2=0, M3=-35`：仅右轮前进 → 绕左轮右转。
  与模拟器 `turn=(left-right)/2`、`heading -= omega*dt`（正 turn=左转）一致。

**D. 停止死区与取值范围**
- 程序内电机停止判定区间 `[−5, 5]`（容错摇杆中值漂移），非 0。
- 转速范围 `-100~100`，超出被钳到 ±100（与固件实证一致）。
- 注：`test.XUANZHI` 的"启动触发"用 `CH1 > 15`，仍是程序自身选择，与官方死区 `5` 是两回事。
